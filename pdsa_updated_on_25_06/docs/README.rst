PDSA-FPGA DFX — Proof-of-Concept for Kria KV260
================================================

Dynamic Function eXchange (DFX) mining accelerator with runtime-swappable
reconfigurable modules (Bitcoin SHA-256d / Kaspa SHA-3).

Directory Structure
-------------------
  rtl/          - HDL sources (SystemVerilog + Verilog wrappers)
  scripts/      - Vivado build TCL, testbenches, simulation
  constraints/  - XDC timing/physical constraints for KV260
  output/       - Build outputs (bitstreams, checkpoints, reports)
  sw/           - Linux userspace software for Kria

Hardware Build (Vivado 2025.2 on Windows)
------------------------------------------
  1. Source the Vivado environment.
  2. Run the "separate RP" flow (produces correct partials):

       cd scripts
       vivado -source vivado_bd_dfx_separate_rp.tcl

     Or the "proper" OOC flow:

       vivado -source vivado_bd_dfx_proper.tcl

     Output bitstreams in D:/pdsa_fpga_dfx_build/output/
       pdsa_full_sep_btc.bit         - full shell + rm_bitcoin
       pdsa_rm_sep_btc.bit           - partial: swap to Bitcoin
       pdsa_rm_sep_kaspa.bit         - partial: swap to Kaspa

  3. The XSA (for Petalinux/Vitis) is generated by vivado_bd_dfx_proper.tcl
     at D:/pdsa_fpga_dfx_build/output/pdsa_dfx.xsa.

Software Build (cross-compile for aarch64, or build natively on Kria)
---------------------------------------------------------------------
  On Kria (Ubuntu):
    cd ps_software
    apt install build-essential
    make clean all
    sudo ./pdsa_main

  Cross-compile (if you have aarch64-linux-gnu-gcc):
    cd ps_software
    make CC=aarch64-linux-gnu-gcc
    scp pdsa_main kria:~/

Deployment on Kria KV260
------------------------
  1. Copy bitstreams to /lib/firmware:

        sudo cp output/pdsa_full_sep_btc.bit.bin      /lib/firmware/
        sudo cp output/pdsa_rm_sep_btc.bit.bin        /lib/firmware/
        sudo cp output/pdsa_rm_sep_kaspa.bit.bin      /lib/firmware/

  2. Load the full shell:

        sudo fpgautil -b /lib/firmware/pdsa_full_sep_btc.bit.bin

  3. (Optional) Apply device tree overlay:

        mkdir -p /configfs/device-tree/overlays/pdsa
        dtc -@ -I dts -O dtb -o ps_software/pdsa_dfx.dtbo ps_software/pdsa_dfx.dts
        cp ps_software/pdsa_dfx.dtbo /configfs/device-tree/overlays/pdsa/dtbo

  4. Run the miner:

        sudo ./pdsa_main

  5. Swap RM at runtime:

        sudo fpgautil -b /lib/firmware/pdsa_rm_sep_kaspa.bit.bin

CSR Register Map (AXI-Lite at 0xA000_0000, 64 KB)
---------------------------------------------------
  Offset  Dir  Description
  ------  ---  -------------------------------------------
  0x00    W    CTRL: {dpr, decouple, stop, start}
  0x00    R    STATUS: {dpr_active, decoupled, found, busy}
  0x08    W    ALGO_SEL (algo_id for next RM)
  0x0C    W    START_NONCE
  0x10-2C W    TARGET[255:0]  (8 x 32-bit LE)
  0x30-4C W    MIDSTATE[255:0]
  0x50-9C W    JOB_DATA[639:0] (20 x 32-bit LE)
  0xA0    W    PT_THRESHOLD
  0xA4    W    PT_CURRENT
  0xA8    W    BCV_STATUS
  0xB0    R    HASH_COUNT[31:0]
  0xB4    R    HASH_COUNT[63:32]
  0xB8    R    GOLDEN_NONCE
  0xBC    R    DPR_LATENCY (cycles)
  0xC0    R    HASHRATE (hashes/window)
  0xC4    R    PDSA_DECISION
  0xC8-E4 R    RESULT_HASH[255:0] (8 x 32-bit LE)

Verification (simulation)
-------------------------
  ModelSim ASE:
    cd scripts
    run_sim.bat

  Each testbench (rm_bitcoin, rm_kaspa) runs 6 tests; 12/12 must pass.

Notes
-----
- The SHA-3-256 in rm_kaspa implements real Keccak-f[1600] (24 rounds
  of theta/rho/pi/chi/iota), matching NIST FIPS 202.
- The AXI-Lite CSR uses word-addressing (addr[11:2]). Software must
  write to byte offsets (addr * 4).
- Partial bitstreams from the "separate RP" BD flow (~309 KB) work
  correctly; the flat-flow partial (8.4 MB) is mislabeled.
